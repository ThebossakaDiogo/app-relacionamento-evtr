# MAGNÉTICA 2.0 — PACOTE PARA LOVABLE
Data: 02/10/2026

Este pacote foi preparado para construir o Magnética como um infoapp mobile-first de pós-término, clareza, comunicação e decisões de contato.

## ORDEM RECOMENDADA

1. Crie um novo projeto no Lovable.
2. Defina Supabase como backend principal.
3. Anexe estes arquivos:
   - 01_PRD_MAGNETICA_2.md
   - 02_DESIGN_MAGNETICA_2.json
   - 03_CONTEUDO_INICIAL_MAGNETICA_2.md
   - 04_ARQUITETURA_E_DADOS.md
   - 05_DATABASE_STARTER.sql
   - 06_PROMPTS_LOVABLE.md
   - 07_PROTOTIPO_MAGNETICA_2.html
4. Cole o conteúdo de 08_MASTER_PROMPT.txt.
5. Faça a implementação por fases. Não tente implementar pagamentos e IA real na primeira execução.

## PRIORIDADE

A prioridade do produto é:
- onboarding contextual;
- plano adaptativo de 28 dias;
- home "Hoje";
- Devo mandar mensagem?;
- Ele me chamou;
- Laboratório de mensagens;
- Fato ou interpretação?;
- check-in;
- linha do tempo;
- diário;
- biblioteca;
- progresso.

## POSICIONAMENTO

Categoria:
Plano Personalizado Pós-Término.

Promessa interna:
"Clareza para saber qual pode ser o seu próximo passo depois do término — inclusive quando tudo muda."

Não construir como:
- curso genérico de autoestima;
- dashboard SaaS corporativo;
- "máquina para fazer ex voltar";
- app que promete controlar sentimentos ou decisões de terceiros.

## PRINCÍPIOS

- Fatos antes de interpretações.
- Ações antes de promessas.
- Reciprocidade antes de perseguição.
- Clareza antes de impulso.
- Autonomia antes de dependência do aplicativo.
- Sem garantias sobre o comportamento de outra pessoa.
- Sem diagnóstico psicológico.
- Sem "score de chance de voltar".
- Sem gatilhos de ciúme, triangulação, chantagem ou perseguição.
- Conteúdo íntimo não vai para analytics.
- Diário e mensagens são privados por padrão.

## ARQUIVOS

01_PRD_MAGNETICA_2.md

02_DESIGN_MAGNETICA_2.json

Schema inicial para Supabase/Postgres com RLS básico.

06_PROMPTS_LOVABLE.md
Prompts separados por fase para construir sem desorganizar o projeto.

07_PROTOTIPO_MAGNETICA_2.html
Referência visual local. Não considerar como app final nem como fonte de lógica.

08_MASTER_PROMPT.txt
Prompt inicial curto para o Lovable.

## DEFINIÇÃO DE PRONTO DO MVP

O MVP está pronto somente quando uma usuária consegue:

1. criar conta;
2. concluir o Mapa do Momento;
3. receber um plano coerente;
4. ver a missão atual;
5. registrar se houve contato;
6. usar "Devo mandar mensagem?";
7. usar "Ele me chamou";
8. preparar e salvar/copiar uma mensagem;
9. registrar linha do tempo;
10. completar um dia;
11. registrar check-in;
12. acessar diário privado;
13. retomar progresso em outro dispositivo.

Não marcar IA, pagamentos, áudios ou integrações como concluídos se estiverem simulados.
